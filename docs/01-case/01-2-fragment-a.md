# 01-2 · A fragment：16×16 怎么分给 32 个线程

这一讲我们要把一个 16×16 的 f16 矩阵，摊到 32 个线程的寄存器里。
听起来像个小问题，但它是整门课最重要的推导，因为**后面所有"为什么这条 IR 长这样"
的问题，答案都在这里**。

## 一、先搞清楚"fragment"到底指什么

`mma.sync` 不是普通的函数调用。它是一条 **warp 级指令**：你写一行，等价于
一个 warp 的 32 个线程同时执行一条硬件指令，一起完成一次矩阵乘累加。

这就带来一个后果：**操作数不是"一个矩阵"，而是"32 个线程各自手里的一小把寄存器"**。

我们把这一小把寄存器叫 **fragment**（片段）。所以有四个 fragment：

| 名字 | 是什么 | 每个线程拿几个寄存器 |
| --- | --- | --- |
| A | 16×16 的 f16 | 4 个 `.b32`（每个装 2 个 f16） |
| B | 16×8 的 f16 | 2 个 `.b32` |
| C / D | 16×8 的 f32 | 4 个 `.f32` |

这一讲只讲 A。但你别急着记结论，**我要把这张表推出来给你看**——因为推导的方法，
你在 B 和 C/D 上要再用两遍。

## 二、两个坐标：lane、gid、tig

一个 warp 32 个线程，硬件给每个线程一个编号 `lane`（即 `threadIdx.x % 32`，
在我们这个"一个 block 一个 warp"的案例里就是 `threadIdx.x`），取值 0..31。

这个 32 怎么切？先看一行里有多少个"位置"。

一条 `m16n8k16` 的 A 是 16×16。注意它的 **K 方向是 16**。而硬件把 K 方向切成两半来分配，
每半个是 8。所以你会看到 4 个 8×8 的小块——这是后面所有布局的来源。

先定义两个量（源码里就是这么写的）：

```cpp
const int gid = lane >> 2;    // 0..7    组号
const int tig = lane &  3;    // 0..3    组内编号
```

换个说法：

```
lane = gid * 4 + tig
```

为什么要这么切？你可以这样理解：

- **tig（组内编号，0..3）负责"K 方向上的偏移"**。因为每个 `.b32` 寄存器装 2 个 f16，
  而 tig 有 4 个取值，正好覆盖 4×2 = 8 个 K 位置——**刚好是半个 K 的宽度**。
- **gid（组号，0..7）负责"行/列"**。它有 8 个取值，而 A 有 16 行，所以
  每个 gid 要负责两行（第 `gid` 行和第 `gid+8` 行）。这个"8 → 16"的翻倍，
  由寄存器数量来抵：A 有 4 个寄存器，其中 2 个管首行、2 个管尾行。

这段话如果你觉得有点绕，没关系，下面用"数数"的方式再推一遍，会清楚得多。

## 三、用"数数"推一遍：A 有 4 个寄存器，每个装 2 个 half

已知：

```
A 的元素数 = 16 行 × 16 列 = 256 个 f16
warp 线程数 = 32
```

所以每个线程应该拿到：

```
256 / 32 = 8 个 f16
```

而一个 32 位寄存器 `.b32` 能装 2 个 f16。所以：

```
8 / 2 = 4 个 .b32 寄存器
```

于是我们有了 `a[0]`、`a[1]`、`a[2]`、`a[3]`。**这一步没有任何魔法，就是除法和装箱。**
同样的算法你可以在 B（16×8 → 128 个元素 → 每个线程 4 个 half → 2 个寄存器）
和 C/D（16×8 个 f32 → 每个线程 4 个 float → 4 个寄存器）上重做一遍。

真正需要查手册的，是"**哪一个寄存器装哪几个元素**"——也就是布局。

## 四、ISA 规定的 A 布局

PTX ISA 对 `m16n8k16.row.col.f32.f16.f16.f32` 的 A 是这样定义的（我把图翻译成公式）：

```
a[0] 的低 half = A[gid]    [2*tig]        a[0] 的高 half = A[gid]    [2*tig + 1]
a[1] 的低 half = A[gid+8]  [2*tig]        a[1] 的高 half = A[gid+8]  [2*tig + 1]
a[2] 的低 half = A[gid]    [2*tig + 8]    a[2] 的高 half = A[gid]    [2*tig + 9]
a[3] 的低 half = A[gid+8]  [2*tig + 8]    a[3] 的高 half = A[gid+8]  [2*tig + 9]
```

写成表格（这是我们这门课要背的第一张表）：

| 寄存器 | 第 0 个 half（低 16 位） | 第 1 个 half（高 16 位） |
| --- | --- | --- |
| `a[0]` | `A[gid][2*tig]` | `A[gid][2*tig+1]` |
| `a[1]` | `A[gid+8][2*tig]` | `A[gid+8][2*tig+1]` |
| `a[2]` | `A[gid][2*tig+8]` | `A[gid][2*tig+9]` |
| `a[3]` | `A[gid+8][2*tig+8]` | `A[gid+8][2*tig+9]` |

现在把这张表和"数数"的结论对照一下：

- 每个线程 4 个寄存器 ✓
- 每个寄存器 2 个元素 ✓
- **同一个寄存器里的两个 half 是同一行相邻的两个 K**（`2*tig` 和 `2*tig+1`）
  → 这一点很关键，它意味着**在内存里这两个 half 是连续的**，
  所以可以一次 `load i32` 拿走它们。第 3 部分读 IR 时你会看到这条 `load i32`。

## 五、换个角度：16×16 的 A 被切成四个 8×8

上面那张表如果只是背，很容易记混。我建议你记住它的"形状"：

```
                    k = 0..7                 k = 8..15
              ┌──────────────────────┬──────────────────────┐
   row 0..7   │        a[0]          │        a[2]          │
              │  行 = gid            │  行 = gid            │
              │  列 = 2*tig, 2*tig+1 │  列 = 2*tig+8, +9    │
              ├──────────────────────┼──────────────────────┤
   row 8..15  │        a[1]          │        a[3]          │
              │  行 = gid+8          │  行 = gid+8          │
              │  列 = 2*tig, 2*tig+1 │  列 = 2*tig+8, +9    │
              └──────────────────────┴──────────────────────┘
```

四句话：

1. **左右两半按 K 分**（K=0..7 和 K=8..15），对应 `a[0]/a[1]` 和 `a[2]/a[3]`。
2. **上下两半按行分**（行 0..7 和行 8..15），对应 `a[0]/a[2]` 和 `a[1]/a[3]`。
3. **每个 8×8 小块里，16 个线程（tig × 2 个 half）负责一行的 8 个 K，
   8 个 gid 负责 8 行**——刚好铺满。
4. 每个线程在每个小块里拿 2 个元素，四个小块一共 8 个元素 ✓。

## 六、那个"反直觉"的点：a[1] 和 a[2] 的顺序

上面这张图里，四个寄存器的编号顺序是：

```
a[0] = 左上    a[1] = 左下    a[2] = 右上    a[3] = 右下
```

注意：**是"先上下、后左右"，不是"先左右、后上下"。**

为什么会这样？因为 `mma` 指令的硬件设计就是按这个顺序吃寄存器的。
这件事看起来是个无关紧要的细节，但它有个非常实际的后果——第 7 部分讲 `ldmatrix` 时你会看到：

> `ldmatrix.x4` 让 lane 0–7、8–15、16–23、24–31 分别提供四个 8×8 小块的地址，
> 而**这四个小块的顺序必须按 `a[0], a[1], a[2], a[3]` 排**，也就是"左上、左下、右上、右下"。

很多人第一次手写 `ldmatrix.x4` 会按"左上、右上、左下、右下"（从左到右、从上到下）去排地址，
结果 `a[1]` 和 `a[2]` 装反，算出来的结果是错的。**这个坑我们待会儿在 01-3 和 07-3 都会再提一次。**

## 七、在源码里，这一步对应哪几行

回到 [`code/tc_mma.cu`](../../code/tc_mma.cu)，A 的装载在 v1 里长这样：

```cpp
const int a_r0 = gid, a_r1 = gid + 8;          // 行：gid 与 gid+8
const int a_c0 = tig * 2, a_c1 = tig * 2 + 8;  // 列：两组，各差 8

const __half *pa0 = A + (tile_m + a_r0) * K + k0 + a_c0;
const __half *pa1 = A + (tile_m + a_r1) * K + k0 + a_c0;
a[0] = pack_half2(pa0);        // row gid,    k 2t .. 2t+1   ← 一次 32 位 load 拿 2 个 half
a[1] = pack_half2(pa1);        // row gid+8,  k 2t .. 2t+1
a[2] = pack_half2(pa0 + 8);    // row gid,    k 2t+8 .. 2t+9 ← +8 就是 a_c1 与 a_c0 的差
a[3] = pack_half2(pa1 + 8);    // row gid+8,  k 2t+8 .. 2t+9
```

其中：

```cpp
__device__ __forceinline__ uint32_t pack_half2(const __half *p) {
  return *reinterpret_cast<const uint32_t *>(p);
}
```

**这一段里藏着这门课的一个"梗"**：注意 `a[4]` 用的不是 `__half` 类型，而是 `uint32_t`。
我们故意用"32 位整数视角"去看这两个 half。为什么？因为这样做：

- 前端会发一条 `load i32`（一次拿两个 half），而不是两条 `load i16` 加一次打包；
- 后面 PTX 里就是一条 `ld.global.nc.b32`；
- SASS 里就是一条 `LDG.E.CONSTANT`。

如果你老实按 `__half` 一个个取，编译器会给你两条 `load i16` 加一条 `mov.b32` 打包指令
（`__halves2half2` 的胶水代码）。第 2 部分我们会实际对比这两种写法的 IR。

## 八、怎么验证你没有算错

纸上推完，最好在机器上验一遍。我给你一个最简单的思路：**让每个线程把自己手上的
8 个元素打印出来**，然后和公式对照。

```cpp
// 临时加在 kernel 里（只用一个 block 跑，lane 0..31）
if (blockIdx.x == 0 && blockIdx.y == 0) {
  printf("lane=%2d gid=%d tig=%d | a0=(%d,%d) a1=(%d,%d) a2=(%d,%d) a3=(%d,%d)\n",
         lane, gid, tig,
         gid, 2*tig, gid+8, 2*tig, gid, 2*tig+8, gid+8, 2*tig+8);
}
```

跑起来你会看到 32 行，每一行是一个线程负责的"坐标"。拿 lane = 13 举例：

```
lane=13 → gid=3, tig=1 → a0=(3,2) a1=(11,2) a2=(3,10) a3=(11,10)
```

**这四条坐标，就是第 3 部分读 IR 时那四条 `load i32` 的地址来源。**
等你读到那儿，可以把两边对着看。

顺便说一句，验证 fragment 布局最硬的办法不是打印坐标，而是**对拍数值**：
我们的 kernel 最后会算 `max |D - ref|`，和 CPU 上的 fp32 参考实现比。
如果布局错了，误差不会是 1e-6 这个量级，而是直接炸开——我们在 v2 里就见过一次
`max |D - ref| = 13.9497`，那个数字背后就是 `.trans` 配错了布局（第 7 部分细讲）。

## 九、小结

1. fragment = "32 个线程各自手里那一小把寄存器"。A 有 4 个 `.b32`，
   这是 `256 个 f16 ÷ 32 线程 ÷ 2 个/寄存器` 算出来的。
2. A 的布局可以用"四个 8×8 子块"来记：**左右分 K、上下分行**，
   寄存器顺序是 `a[0]=左上, a[1]=左下, a[2]=右上, a[3]=右下`。
3. 每个寄存器里的两个 half **在内存里是连续的**——这是 A 的装载能用
   "一次 32 位 load"搞定的原因，也是 A 和 B 最本质的区别（下一讲就讲 B）。
