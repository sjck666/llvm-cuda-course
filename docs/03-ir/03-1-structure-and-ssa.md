# 03-1 · IR 的四层结构与 SSA

这一讲讲两个"读 IR 前必须先有的概念"。它们不是 LLVM 特有的，但你如果不熟悉，
后面每读一行都会卡一下。

## 一、四层嵌套：Module → Function → BasicBlock → Instruction

LLVM IR 的结构是严格嵌套的，只有四层：

```
Module                  ← 一个编译单元（对我们来说 = 一个 .cu 的设备端部分）
 └── Function           ← 一个函数（= 一个 kernel 或一个 __device__ 函数）
      └── BasicBlock    ← 一段直线代码，只有一个入口、一个出口
           └── Instruction   ← 一条指令
```

看我们的 `dumps/02-device-O2.ll`：

```
第 12 行   define dso_local ptx_kernel void @mma_tc_manual(...)   ← Function 开始
第 13 行     %7 = tail call noundef i32 @llvm.nvvm...            ← Instruction
  ...
第 27 行   19:                                                    ← BasicBlock（标签）
第 33 行   23:                                                    ← 另一个 BasicBlock
  ...
第 50 行   38:                                                    ← 写回块
第 76 行   58:                                                    ← 循环头
  ...
第 117 行 }                                                       ← Function 结束
```

**BasicBlock 的两个规矩**：

1. 只有一个入口（标号所在处），只能从标号处进入；
2. **只能有一个出口**，而且出口必须是最后一条指令（`br`、`ret`、`switch` 之类）。

所以你在 IR 里看到 `br i1 %17, label %23, label %19` 这种写法时，
要意识到：**这一条指令同时决定了两个后继块**，它就是"这个块的脸"。

### 为什么我们能在 IR 里看到"行号"和"标号"

因为这是**文本表示**。IR 在内存里是对象（`Module`、`Function`、`BasicBlock`、
`Instruction` 类），写成文本时才会出现数字标号。

数字标号是给没有名字的块用的（名字在优化过程中被丢掉了——
命令行里那个 `-discard-value-names` 就是干这个的）。所以你看 `%23` 这种编号时，
不要试图从中读出"这是第几个循环"，**它只是编译器内部的编号**。

## 二、SSA：每个值只被赋值一次

**SSA = Static Single Assignment（静态单赋值）**。规矩只有一条：

> **每个变量（`%0`、`%1`……）只被赋值一次。**

所以你会看到这种风格：

```llvm
%12 = lshr i32 %7, 2        ; gid = lane >> 2
%13 = add nuw nsw i32 %12, 8
%14 = shl nuw nsw i32 %7, 1
```

每一条指令产生一个**新名字**，永远不会出现 `%12 = ...` 第二次。

这在"直线代码"里很自然。问题出在**分支和循环**上：如果一个值在不同路径上
有不同的来源怎么办？SSA 的答案是 **phi 节点**。

### phi 长什么样

看我们循环的头部（`dumps/02-device-O2.ll` 第 76–81 行）：

```llvm
58:                                    ; preds = %23, %58
  %59 = phi i32 [ 0, %23 ], [ %96, %58 ]
  %60 = phi float [ 0.000000e+00, %23 ], [ %92, %58 ]
  %61 = phi float [ 0.000000e+00, %23 ], [ %93, %58 ]
  %62 = phi float [ 0.000000e+00, %23 ], [ %94, %58 ]
  %63 = phi float [ 0.000000e+00, %23 ], [ %95, %58 ]
```

读法：**"如果我是从 `%23` 进来的，我的值是 `0`；如果我是从 `%58` 进来的
（也就是循环回到自己），我的值是 `%96`。"**

翻译成源码就是：

```cpp
for (int k0 = 0; ...) { ... }     // %59 = k0：第一次进来是 0，之后是上一轮的 k0+16
float c[4] = {0,0,0,0};           // %60..%63：第一次进来是 0，之后是上一轮算出来的 D
```

**这五个 phi 就是源码里"跨迭代存活"的五个变量。** 第 03-4 讲会拿它们当主线
把整个循环读一遍。

### 一个反直觉的事实：phi 是"前驱块的选择"，不是"赋值"

初学者常把 phi 理解成"在块开头赋值"。更准确的理解是：

> **phi 在块入口处，根据"从哪个前驱块跳过来"来选一个值。**

所以 phi 的操作数一定是**和这块的前驱块一一对应**的。你看 `%59` 有两个前驱
（`%23` 和 `%58`），所以有两个候选值——数量必须对得上，否则 IR 是坏的。

## 三、类型系统：显式类型 + 指针带地址空间

IR 的另一个特点：**每个值都带类型，不省略**。

```llvm
%12 = lshr i32 %7, 2        ; i32 是显式写的
%60 = phi float [...]       ; float 也是显式写的
```

指针也一样，而且**指针带地址空间**：

```llvm
ptr                       ; 地址空间 0（generic）
ptr addrspace(1)          ; global
ptr addrspace(3)          ; shared
```

第 02-3 讲我们已经把地址空间讲透了，这里只强调一个使用习惯：

> **看到 `load` / `store` / `getelementptr` 时，第一件事是看它的指针在哪个地址空间。**
> 地址空间决定了后端用哪条访存指令，也决定了性能。

另外注意：**新版 LLVM 的指针是"不透明指针"（opaque pointer）**。
你会看到 `ptr`、`ptr addrspace(3)` 这种写法，而**看不到**老版本里的
`float*`、`i32*`。类型信息被挪到了 `load` / `store` / `getelementptr` 上：

```llvm
%68 = load i32, ptr %67, align 4       ; 读一个 i32，从 ptr 读
%26 = getelementptr inbounds nuw [2 x i8], ptr %0, i64 %25   ; 按 [2 x i8] 为单位走
```

这是新版 LLVM 和很多老资料最大的书写差异。**看到 `ptr` 不要慌，看指令上的类型就行。**

## 四、两种世界：内存世界 vs 值世界

读 IR 时最有用的一个思维模型是：

```
内存世界                             值世界
alloca / load / store                SSA 值（%xx）+ phi
"一块内存，能被取地址、能被越界"        "一个不可变的值，直接进寄存器"
```

**优化器的大部分工作，就是在把代码从内存世界搬到值世界。**

我们的案例里这个过程非常明显（第 03-5 讲会用数字对比）：

```llvm
; O0（内存世界）：数组在栈上，每次用之前 load 出来
%199 = load i32, ptr %198, align 4          ; a[0]

; O2（值世界）：直接是 SSA 值
%68 = load i32, ptr %67                     ; 直接从 global 读，没有中间 alloca
```

O0 里 `float c[4]`、`uint32_t a[4]` 这些数组**真的存在**（有 `alloca`），
O2 里它们**彻底消失**，变成了 phi 和 SSA 值。

而完成这个搬运的，就是第 4 部分要讲的两个 pass：**SROA 和 mem2reg**。

## 五、小结

1. IR 是四层嵌套：Module → Function → BasicBlock → Instruction。
   BasicBlock 只有一个入口，出口只能是最后那条终结指令。
2. SSA 规矩是"每个值只赋值一次"，分支/循环处的合并靠 **phi**——
   phi 是"按前驱块选值"，操作数个数必须等于前驱个数。
3. 读 IR 的两个习惯：**看指针的地址空间**、**分清"内存世界"和"值世界"**。
   优化器干的主要工作之一，就是把后者从前者里解放出来。
