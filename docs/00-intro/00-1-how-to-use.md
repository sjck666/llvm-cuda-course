# 00-1 · 这套课怎么上

同学你好，我是这门课的讲解者。在给你看第一行 CUDA 代码之前，我想花一讲的时间，
先说清楚"我们到底在干什么"，以及"你该怎么用这份材料"。

因为这门课有点特别：它既不是 CUDA 教程，也不是 LLVM 源码导读。它是**一条链路的解剖课**。

## 一、先说说这门课要解决的那个真问题

我猜你大概率遇到过下面这些情况中的至少一个：

- 你写了一个 Tensor Core 的 kernel，能跑，结果也对，但你**说不清**为什么它只能跑出这点性能；
- 你打开 SASS 看了一眼，满屏 `HMMA.16816.F32 R8, R12, R26, R8`，你只知道它"是矩阵乘"，
  但不知道那四个寄存器分别是什么；
- 你听说过 `convergent` 这个词，也知道它"跟同步有关"，但你说不出它到底挡住了哪些优化；
- 你写过一行内联汇编 `asm volatile("mma.sync...")`，然后发现周围代码的优化质量莫名其妙变差了；
- 你想给 LLVM 加一条新指令，打开 `llvm/lib/Target/` 一看，几百个文件，不知道从哪儿下手。

这些问题的共同点是：**它们都卡在"中间那一层"**。

你上面能看到 CUDA C++，下面能看到 SASS，但中间那四五层——Clang 怎么把 `__shared__` 变成
地址空间、LLVM IR 为什么长成那样、中端做了哪些手脚、后端怎么把 IR 变成机器指令——
是一段黑箱。黑箱不可怕，可怕的是**调试和调优的时候你必须打开它**。

所以这门课只干一件事：**我们找一个足够小、又足够完整的例子，把这条链路的每一站都停下来，
看清楚它在这一站变成了什么、为什么变成这样。**

## 二、我们的例子是什么

就一个文件：[`code/tc_mma.cu`](../../code/tc_mma.cu)，270 行，里面两个 kernel：

```cpp
mma_tc_manual     // v1: 手动从 global memory 组装 fragment，不碰 shared memory
mma_tc_ldmatrix   // v2: cp.async 搬 tile 到 shared memory + ldmatrix 装 fragment
```

它们做同一件事：算 `D = A × B`，其中 A 是 16×16 的 f16、B 是 16×8 的 f16、D 是 16×8 的 f32——这是
一条 `mma.sync.aligned.m16n8k16.row.col.f32.f16.f16.f32` 指令的形状。

为什么选这么小的尺寸？因为**小到你可以在纸上把寄存器账算清楚**。

如果你写过 CUTLASS 或者 CuTe，你可能会想："真实项目哪有这么写的"。对，真实项目不这么写。
但这门课要看的不是"工程上怎么写"，而是"**编译器把你的写法变成了什么**"。
CUTLASS 会在中间插进大量模板元编程和它自己的抽象层，最后 dump 出来的东西是
"CUTLASS 的 lowering + LLVM 的 lowering"混在一起，初学者根本分不清哪一层是哪一层的锅。

**手写 60 行 fragment 代码，换来的是：每一行 IR 你都能对回自己的源码。**
这个交换我觉得非常值。

## 三、这门课要回答的五个问题

整条链路走完，我们会反复回到这五个问题上：

1. **CUDA 特有的东西（`__global__`、`__shared__`、`threadIdx`、`__syncthreads`）
   在 LLVM IR 里变成了什么？**
   ——这是前端的事。

2. **`-O2` 中间那些 pass 把我们的代码改成了什么样？**
   ——这是中端的事。你会看到数组消失、循环展开、以及一条谁都没想到的 `convergent` 标记。

3. **LLVM 的后端到底是怎么搭起来的？一套后端要提供哪些东西，才能把一个通用 IR
   变成某台机器的指令？**
   ——这是第 5 部分的事，也是这套课里篇幅最大的一块。我们会把 TargetMachine、
   TableGen、SelectionDAG、指令选择、寄存器分配、调度、汇编发射**一层一层拆开讲**。

4. **PTX 里那几条怪怪的指令（`mma` / `ldmatrix` / `cp.async`）到底在说什么？**
   ——这是第 7 部分的事。

5. **最后的 SASS 里，`HMMA` 的四个操作数分别对应我源码里的哪一个变量？**
   ——这是第 8 部分的事。这条链路只有闭环到这里，你才算真正看懂了。

## 四、每一讲的结构

为了让你读起来不像在读手册，每一讲我都按同一个套路组织，你也可以按这个套路去检验
自己有没有读懂：

```
1. 提出问题        —— 这一讲我们要解决什么？为什么值得单独讲？
2. 给出命令        —— 你能直接粘贴执行的命令（不是伪代码）
3. 看真实输出      —— 这台机器上跑出来的，一个字符都不改
4. 逐行拆解        —— 输出里的每一行在说什么，哪些地方反直觉
5. 反面案例        —— 我踩过的坑，或者"想当然会怎样、实际会怎样"
6. 小结 + 动手题    —— 三句话总结，加一两个你可以自己跑的实验
```

特别是第 5 条。**只讲正确答案的教材不好用**，因为你在自己动手时遇到的往往是错误答案。
所以凡是我们在开发过程中真的踩过的坑（比如 `ldmatrix.trans` 转了两遍导致误差变成 13.9），
我都会原样讲出来。

## 五、这份教材有两套文本

你在仓库里会看到两个目录：

**`docs/`（就是这里）：讲义，逐字稿。**
一讲只解决一两个问题，篇幅长、口语化、有推导过程、有失败记录。适合第一次学。

**`notes/`：浓缩笔记。**
就是原来那 10 章，一张表接一张表，信息密度拉满，几乎没有废话。适合复习和查数字。

我的建议是：

```
读一讲讲义  →  跑一遍这一讲里的命令  →  翻 notes/ 里对应的那张表当速查
```

如果你已经很熟这块内容，只是想确认某个具体数字（比如"ptxas 报了几个寄存器"），
直接去 `notes/`，别在讲义里翻。

## 六、前置知识：这门课假设你会什么

我不假设你是 LLVM 专家，但假设你具备这些：

| 要求 | 到什么程度 |
| --- | --- |
| C++ | 看得懂模板和 `reinterpret_cast`；我们的案例代码只用到这些 |
| CUDA 基础 | 知道 kernel、block、warp、`threadIdx`、shared memory 是什么 |
| 汇编 | 看得懂寄存器-操作数风格的伪汇编（`add r1, r2, r3` 这种）就够 |
| 编译原理 | **不需要**。SSA、phi、DAG 这些概念，我们用到的时候现讲 |
| Python / shell | 会跑脚本、会 `grep` 就行 |

有一件事我要提前说清楚：**这门课不教你 CUDA 编程**。我们不会讲怎么设计一个高性能 GEMM，
不会讲 occupancy 怎么调、bank conflict 怎么避免。这些话题在别处有更好的材料。
我们只关心"**编译器视角**"：你写下的东西，一路变成了什么。

## 七、几个常见误区，先打个预防针

**误区一："LLVM 后端就是指令选择。"**

这是最常见的一个误解。指令选择（ISel）只是后端流水线中间的一小段。真要说的话，
后端要做的事情至少有这些：

```
把 IR 调成目标机友好的形状 → 指令选择 → 机器层优化 → 寄存器分配
                          → 指令调度 → 前导/后记代码 → 发射汇编或目标文件
```

而且不同目标机的"活"分布得完全不一样。第 5、6 部分我们会看到极端例子：
**NVPTX 后端根本不自己做寄存器分配**——它把这件事推给了 ptxas。

**误区二："LLVM 的 IR 是稳定的，不同版本差不多。"**

不是的。这门课里到处是这样的例子：

- 老版本用 `!nvvm.annotations` 元数据标记 kernel，新版本改成了 `ptx_kernel` calling convention；
- `__syncthreads()` 对应的 intrinsic 从 `llvm.nvvm.barrier0` 改名成了
  `llvm.nvvm.barrier.cta.sync.aligned.all`；
- 同一条 `-O2` 命令，老版本不展开我们的 k 循环，新版本展开了。

所以第 00-2 讲我们要先把版本钉死，并且在后面每一讲里都告诉你"这个结论是在哪个版本下成立的"。

**误区三："看到 PTX 里出现了 `mma.sync` 就说明我写对了。"**

恰恰相反。我们会在第 9 部分看到：**intrinsic 名字写错的时候，有些版本的 LLVM 不报错，
只是默默给你一条函数调用**，你的 kernel 照编译、照运行（或者跑出神奇的结果），
但性能全没了。判断"真的选出了指令"的标准只有一个：去 PTX 里找那一行指令本身。

## 八、本讲小结

三句话：

1. 这门课不讲 CUDA 编程，讲的是**一个具体 kernel 的编译链路**，每一站都停下来看。
2. 例子小到能在纸上算寄存器账，这是刻意的选择——**可验证性比真实性更重要**。
3. 讲义（`docs/`）用来学，笔记（`notes/`）用来查；每一讲都配能直接粘贴的命令和真实输出。

## 九、动手题

1. 打开 [`code/tc_mma.cu`](../../code/tc_mma.cu)，只做一件事：数一数两个 kernel
   各有多少行，猜一猜哪几行会在 IR 里变成"值得讲"的东西。带着这个猜测去读第 1 部分。
2. 在仓库根目录跑一遍 `bash tools/build-and-run.sh`。你不需要看懂它的输出，
   只需要确认一件事：**你这台机器上这套链路是通的**（两个 `PASS`）。

下一讲，我们把环境钉死：你的 clang 是哪一版、CUDA 装在哪、GPU 是什么，
以及一条能一次性把这些都打印出来的自检命令。
